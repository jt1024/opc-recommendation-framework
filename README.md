## 🎯 这是什么

一个用于**生成"一人公司"行业推荐文档**的写作框架 + 自动化校验工具，基于 OPC（One-Person Company）043 实践提炼，输出文档质量基线 **17,000-23,000 字 · 148 分制（≥ 90% 即约 133 分可发布）**。

当给定 **行业场景 + 大致需求** 时，本框架输出包含：

- ✅ 20 章节完整闭环（决策层 → 方法层 → 实战层 → 权威层 + 附录）
- ✅ 14 项质量优化（P0/P1/P2 全覆盖）
- ✅ D+R+2M 综合分模型（OPC 全库统一评分）
- ✅ 用户画像匹配 · 现金流规划 · 法律合规 · 失败案例
- ✅ **🆕 自动化校验脚本**（`validate_opc.py` · 单文件 / 批量模式 · CI/CD 可用）
- ✅ **🆕 禁止模式库**（14 条红线 + 检测正则 + 修复示例）
- ✅ **🆕 写作前/后清单**（避免返工）

## 🚀 快速开始（v3.1 新版）

### 5 步工作流（脚本 + 清单双保险）

```
┌─────────────────────────────────────────────────────────────────┐
│ Step 1 · 写作前：过 pre-write-checklist（8 关 · 30 分钟）         │
│   ↓                                                              │
│ Step 2 · 加载骨架：复制 assets/template-skeleton.md               │
│   ↓                                                              │
│ Step 3 · 按 14 项优化扩写（参考 references/043-quality-benchmark）│
│   ↓                                                              │
│ Step 4 · 写作后：跑 validate_opc.py（自动校验 23 项）            │
│   ↓                                                              │
│ Step 5 · 人工 review：过 post-write-checklist（5 关 · 30 分钟）   │
│   ↓                                                              │
│ PASS ≥ 90 → git commit & 提交 PR                                │
└─────────────────────────────────────────────────────────────────┘
```

### Step 1 · 写作前 8 关

```bash
# 通读清单
cat validation/pre-write-checklist.md

# 关键打钩项：
# - 场景编号已确定
# - D+R+2M 三值已查
# - ★ 段 9 子节素材已预备
# - 第十三章子节顺序已锁定（13.5→13.9）
# - P1-7 工具 D1/D7/D14/D30 已预备
```

### Step 2 · 加载骨架

```bash
cp assets/template-skeleton.md 043_一人数字化转型顾问.md
# 或新文档：
cp assets/template-skeleton.md 044_一人流程优化顾问.md
```

### Step 3 · 按 14 项优化扩写

```bash
# 参考 043 实战
cat references/043-quality-benchmark.md

# 14 项优化清单（P0 × 5 + P1 × 5 + P2 × 4）
cat SKILL.md | grep -A 30 "14 项质量优化"
```

### Step 4 · 跑自动校验（关键步骤）

```bash
# 单文件校验
python assets/validate_opc.py /path/to/044_xxx.md

# 期望输出：
# 📊 总分: 95.00 / 100 (95%)
# 🎯 评级: PASS · 可发布

# 批量校验 OPC 全库
python assets/validate_opc.py --batch /Users/jiatao/Desktop/CodexJT/opc-365/03_一人公司场景推荐/

# 仅输出汇总（适合 CI/CD）
python assets/validate_opc.py --batch /path/ --quiet
```

### Step 5 · 人工 review

```bash
# 跑完脚本后，对照清单补脚本未覆盖项
cat validation/post-write-checklist.md

# 重点关注：
# - META-1 字数实际值与声明偏差
# - META-2 占位符残留扫描
# - META-3 内部链接 / 跳转正确性
```

### 输出文件命名

```
例如：
```

## 🤖 validate_opc.py 使用指南

### 核心能力

`assets/validate_opc.py` 是 v3.1 最重要的新增能力，把"人对照检查"变成"脚本对照检查"。

**23 项自动检查（实际满分 148 分）**：
- META × 2：标题版本号、字数声明
- STRUCT × 3：章节连续 1→15、第十三章顺序、**OPC 主表副本检测（v3.2 新增）**
- P0 × 5：读者筛选、数字分布、本地 20 客户、4 方案现金流、失败案例
- P1 × 5：客户原话、工具上手日记、法律合规、家庭会议、评分依据
- P2 × 4：90 天清单、引用源分组、ASCII 信息图、相近场景跳转
- 其他 × 4：反模式（占位符 + ⭐/梯队错配）、表格渲染、★ 段字数自洽、★ 段子节顺序

> ⚠️ **不是 100 分制**：14 项质量优化（P0+P1+P2）只占 100 分，
> 另有 META 10 分 + STRUCT 20 分 + 其他 4 项，**实际满分为 148 分**。
> 评级按百分比判定，PASS 需 **≥ 90%（148 分制约 133 分）**。

### 三种使用模式

#### 模式 1：单文件校验

```bash
python assets/validate_opc.py /path/to/043_xxx.md

# 输出样例：
# ✅ 标题版本号                            5/5
# ✅ 字数声明                             5/5
# ✅ 章节连续 1→15                      10/10
# ✅ 第十三章顺序                         10/10
# ✅ P0-1 读者筛选                      12/12
# ...
# 📊 总分: 130.00 / 100 (130%)
# 🎯 评级: PASS · 可发布
```

#### 模式 2：批量校验（CI/CD 推荐）

```bash
python assets/validate_opc.py --batch /Users/jiatao/Desktop/CodexJT/opc-365/03_一人公司场景推荐/

# 输出汇总表：
# 📁 批量校验: 365 个文件
# 📊 批量汇总
# 文件                              分数    评级
# 043_一人数字化转型顾问.md           100%  PASS
# 044_一人流程优化顾问.md              78%   NEEDS_IMPROVEMENT
# 045_xxx.md                          62%   FAIL
```

#### 模式 3：仅汇总（CI/CD 集成）

```bash
python assets/validate_opc.py --batch /path/ --quiet

# 只输出汇总表，不显示每份详细报告
# 适合 GitHub Actions / GitLab CI
```

### 退出码（CI/CD 用）

| 退出码 | 含义 | 触发条件 |
|:---:|---|---|
| `0` | PASS | 总分 ≥ 90 |
| `2` | NEEDS_IMPROVEMENT | 75 ≤ 总分 < 90 |
| `1` | FAIL | 总分 < 75 |

可直接用于：

```yaml
# .github/workflows/opc-validate.yml
- name: Validate OPC docs
  run: python assets/validate_opc.py --batch $OPC_DIR --quiet
```

### 单项失败的修复指引

脚本对每项失败会输出：
- `└─` 失败原因（如"未找到 13.5（家庭决策会议）"）
- `💡` 修复建议（如"按 13.5 家庭会议 → 13.6 行动 → 13.7 独特 → 13.8 紧迫 → 13.9 本地 顺序排列"）

如需详细修复示例，参考 `references/forbidden-patterns.md`。

## 📐 D+R+2M 综合分模型

OPC 全库统一评分标准 · **所有子文档必须内联此模型说明**

### 公式

```
OPC 综合分 = D + R + 2M
满分 20 分（M 双倍权重，占比 50%）
```

### 4 维度定义

| 字母 | 含义 | 满分 | 说明 |
|---|---|---|---|
| **D** | Demand 需求度 | 5 | 客户基数、付费意愿、复购频次、区域容量 |
| **R** | Risk 风险系数（高分=低风险）| 5 | 合规难度、获客波动、回款风险、行业周期 |
| **M** | Maturity 行业成熟度 | 5 | 工具链 / SOP / 服务链 / 客群认知（**双倍权重**）|

### 梯队划分（与 ⭐ 数对应 · 强制一致）

| 总分 | 梯队 | ⭐ 数 |
|---|---|---|
| 18-20 | 第一梯队 | ⭐⭐⭐⭐⭐ |
| 16-17 | 第二梯队 | ⭐⭐⭐⭐ |
| 14-15 | 第三梯队 | ⭐⭐⭐ |
| 12-13 | 第四梯队 | ⭐⭐ |
| ≤ 11 | 第五梯队 | ⭐ |

> ⚠️ **v3.1 强制**：决策卡梯队编号与 ⭐ 数必须一致，错一项 = 返工（F-03 红线 · 脚本自动检测）

### 043 实例

```
D4 R3 M4 = 15/20
       ↓
D + R + 2M = 4 + 3 + 4×2 = 15
```

| 维度 | 分值 | 依据 |
|------|----:|------|
| **D=4** | 4/5 | 南沙 + 大湾区制造业 / 跨境电商 / 服务业数字化转型需求密集 |
| **R=3** | 3/5 | 合规要求中等（数据安全/知识产权/客户隐私），但无金融级监管 |
| **M=4** | 4/5 | ERP/MES/CRM/低代码工具链成熟，1 人顾问可独立交付 |

### ⚠️ 严禁使用的错误格式

- ❌ `D4 R3 M4 M2 = 15/20`（4 个独立字母，与 D+R+2M 加权公式矛盾）
- ❌ `D + R + M + M`（未标记加权，含义模糊）
- ❌ `D+R+M1+M2`（041 老格式，非综合分）
- ❌ 单独写 `D/R/M` 数值不解释（读者无法理解）
- ❌ ⭐ 数与梯队不对应（如 15 分写 ⭐⭐⭐⭐）

## 🛠 方法论核心

### 1. 评分矩阵设计（Section 3）

**6-10 维度选取原则**：
- 3-4 个**核心业务能力**（50-60% 权重）
- 1-2 个**硬约束**（合规/数据安全 · 20-30% 权重）
- 1 个**经济性**（10% 权重）
- 1 个**长期价值**（10% 权重）

### 2. ROI 计算公式（Section 6）

```
ROI = (替代前成本 - 替代后成本) × 12 月 / 工具年成本
回本周期 = 工具年成本 / (替代前成本 - 替代后成本) / 12
```

**保守估计折扣**：实际节省取行业基准的 60-70%

### 3. 风险预案双方案模式（Section 7）

每个风险必须给：
- **应对**（预防措施 · 可执行清单）
- **兜底**（真出事的应急方案）

### 4. 用户专属建议结构（Section 13 · v3.1 子节顺序强制）

```
13.1 强匹配项
13.2 风险点
13.3 推荐路径
13.4 现金流规划（13.4.1 单方案 + 13.4.2 4 方案对比 + 13.4.3 最坏兜底）
13.5 家庭决策会议 ← (不是"给你独特建议"！)
13.6 第一步行动 + 13.6.1 90 天清单
13.7 给你独特建议 ← (不是"紧迫提醒"！)
13.8 紧迫提醒 ← (不是"家庭决策会议"！)
13.9 本地 N 目标客户范本
```

> ⚠️ **v3.1 强制**：13.5→13.9 子节顺序必须与模板一致（脚本自动检测 · F-04 红线）

### 5. 决策路径图（段一 · P2-13）

ASCII 流程图，4 项硬筛快速分流：

```
你符合 4 项硬筛吗？
├─ ✅ 全部是 → 进入段二完整方案
├─ ⚠️ 部分是 → 看 ★ 专属建议（画像匹配）
└─ ❌ 都不是 → 跳 OPC 相近场景（附录 2）
```

