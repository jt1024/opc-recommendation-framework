### 评分标度对照

| 评分 | 含义 | 描述模板 |
|------|------|---------|
| 10 | 行业绝对领先 | 「唯一具备 / 行业标杆」 |

### 权重分配建议

| 维度类型 | 权重区间 | 适用场景 |
|---------|---------|---------|
| **核心业务能力** | 50-60% | 必含（3-4 个） |
| **硬约束（合规/数据安全）** | 20-30% | 受监管行业必含（1-2 个） |
| **经济性** | 10% | 必含（1 个） |
| **长期价值** | 10% | 推荐含（1 个） |
| **总计** | 100% | 强制 |

### 加权总分公式

```
加权总分 = Σ(维度评分 × 维度权重) / 10
```

### 验证规则（决策树）

```
冠军得分 ≥80 且领先 ≥10 分 → 直接主推（压倒性）
冠军得分 70-80 且领先 5-10 分 → 主推 + 备选
冠军得分 60-70 且领先 <5 分 → 决策树分流
冠军得分 <60 → 重新选型或扩大对比范围
```

## Part 2：OPC 综合分 · D+R+2M 模型（文档头部引用）

### ⚠️ 必须使用的标准格式

每份子文档头部/决策卡中**必须**使用以下公式：

```
OPC 综合分 = D + R + 2M
满分 20 分（4 维度：D + R + M + 2M = 4+5+6 = 15/20 验证）
```

### 四维度定义

| 字母 | 含义 | 满分 | 说明 |
|---|---|---|---|
| **D** | Demand 需求度 / 市场体量 | 5 | 客户基数、付费意愿、复购频次、区域市场容量 |
| **R** | Risk 风险系数（高分=低风险）| 5 | 合规难度、获客波动、回款风险、行业周期性 |
| **M** | Maturity 行业成熟度 | 5 | 行业基础设施完整度（工具/SOP/服务链/客群认知）；**双倍权重** |

### 加权机制

- M 行业成熟度双倍加权：M × 2 = 占比 10/20（**50%**）
- D 与 R 各占 5/20（25% each）
- 总分 = D + R + 2M
- 加权后总分验证：D(1-5) + R(1-5) + M(1-5)×2 = 3-15（实际范围）

### 梯队划分

| 总分 | 梯队 | ⭐ |
|---|---|---|
| 18-20 | 第一梯队 | ⭐⭐⭐⭐⭐ |
| 16-17 | 第二梯队 | ⭐⭐⭐⭐ |
| 14-15 | 第三梯队 | ⭐⭐⭐ |
| 12-13 | 第四梯队 | ⭐⭐ |
| ≤ 11 | 第五梯队 | ⭐ |

### 文档头部引用模板

```markdown
> **OPC 主表定位**：⭐⭐⭐⭐⭐ **D[1-5] R[1-5] M[1-5] = [N]/20**（第 N 梯队 · #NNN · [类别名]）
> 
> **OPC 综合分 · D+R+2M 模型说明（OPC 全库统一评分标准）**：
> - **D** = Demand 需求度 / 市场体量（满分 5）：客户基数 + 付费意愿 + 复购频次 + 区域容量
> - **R** = Risk 风险系数（满分 5）：合规难度 + 获客波动 + 回款风险 + 行业周期
> - **M** = Maturity 行业成熟度（满分 5）：工具链 + SOP + 服务链 + 客群认知
> - **加权公式**：D + R + 2M = N/20（M 双倍权重，占比 50%）
> - **梯队**：18-20 ⭐⭐⭐⭐⭐ | 16-17 ⭐⭐⭐⭐ | 14-15 ⭐⭐⭐ | 12-13 ⭐⭐ | ≤11 ⭐
```

### ⚠️ 严禁使用的错误格式

| 错误 | 说明 |
|------|------|
| ❌ `D4 R3 M4 M2 = 15/20` | 4 个独立字母，与加权公式 D+R+2M 矛盾 |
| ❌ `D + R + M + M` | 未标记加权，含义模糊 |
| ❌ `D+R+M1+M2` | 041 老格式（模型能力+商业模式），与综合分无关 |
| ❌ `D+R+Margin+Maturity` | 150 老格式（4 个独立维度非加权），与综合分无关 |
| ❌ 单独写 `D/R/M` 数值不解释 | 读者无法理解公式 |

### 综合分写作规则（决策卡 + 引用源 + 附录 1）

**决策卡一行**（极简）：
```
OPC 综合分 | D4 R3 M4 = 15/20 ⭐⭐⭐ 第 3 梯队
```

**附录 1 完整说明**（详见 [[template-skeleton]] Part 5 附录 1 模板）：
- D=N 的 4-5 个数据点 + 来源 + 评分依据
- R=N 的 4-5 个数据点 + 来源 + 评分依据
- M=N 的 4-5 个数据点 + 来源 + 评分依据
- 综合分验证公式
- 评分质疑路径说明

## Part 3：043 实例 · 一人数字化转型顾问

### OPC 综合分计算

```
D4 R3 M4 = 15/20
       ↓
D + R + 2M = 4 + 3 + 4×2 = 15
```

### 各维度评分依据

| 维度 | 分值 | 依据 |
|------|----:|------|
| **D=4** | 4/5 | 南沙 + 大湾区制造业 / 跨境电商 / 服务业数字化转型需求密集；中小企业客户基数 10000+；获客难度中等 |
| **R=3** | 3/5 | 合规要求中等（数据安全 / 知识产权 / 客户隐私），但无金融级监管；获客波动中等 |
| **M=4** | 4/5 | ERP/MES/CRM/低代码工具链成熟；1 人顾问可独立交付；SOP 模板丰富；服务链完整 |

### 总分验证

```
D + R + 2M = 4 + 3 + 8 = 15/20
梯队：⭐⭐⭐ 第三梯队
定位：企业服务（中型客户）
```

## Part 4：矩阵评分 vs 综合分的关联

### ⚠️ 两套评分并存

OPC 推荐文档中**存在两套评分系统**，必须区分：

| 评分系统 | 位置 | 公式 | 范围 | 用途 |
|----------|------|------|------|------|
| **Section 3 矩阵评分** | 三、维度适配度评分 | Σ(评分×权重)/10 | 1-10 分 | 工具间对比（哪款工具最强） |
| **OPC 综合分** | 文档头/决策卡 | D + R + 2M | 1-20 分 | OPC 主表定位（场景值不值得做） |

### 关联方式

```
                    ┌─────────────────────────────────┐
                    │ OPC 综合分（D+R+2M）= N/20       │
                    │ 维度 1：D 市场需求               │
                    │ 维度 2：R 风险系数               │
                    │ 维度 3：M 行业成熟度（双倍权重）  │
                    └─────────────────────────────────┘
                                  ↑
                            文档主表定位
                                  
                    ┌─────────────────────────────────┐
                    │ Section 3 矩阵评分 = N/10        │
                    │ 维度 1：核心业务能力（50-60%）    │
                    │ 维度 2：硬约束（20-30%）          │
                    │ 维度 3：经济性（10%）             │
                    │ 维度 4：长期价值（10%）           │
                    └─────────────────────────────────┘
                                  ↑
                            工具选型决策
```

### 写作规则

1. **文档头 / 决策卡**：只写 OPC 综合分（D+R+2M = N/20）
2. **Section 3**：只写工具矩阵评分（加权总分 /10）
3. **两个数字不要混用**：综合分是场景评估，矩阵分是工具评估
4. **附录 1 评分依据**：必须包含 OPC 综合分（D+R+2M）的详细数据点
