# OPC 行业推荐文档 · 完整方法论

> 本文档为 `opc-recommendation-framework` skill 的深度方法论参考。

## 一、文档定位理论

### 1.1 三层内容架构

```
顶层：决策框架（Section 1-4）
├─ 读者用 30 秒判断"要不要继续读"
└─ 含需求画像、痛点、评分、推荐

中层：执行框架（Section 5-9）
├─ 读者用 60 分钟理解"怎么做"
└─ 含落地、ROI、风险、决策速查、行业提醒

底层：实证与个性化（Section 10-14 + 来源）
├─ 读者用 30 分钟确认"真实可信 + 适合自己"
└─ 含案例、迁移、上下游、专属建议、资质、来源
```

### 1.2 目标读者分层

| 读者类型 | 阅读目标 | 推荐章节 |
|---------|---------|---------|
| **快速决策者**（老板/投资人） | 判断 ROI 和可行性 | 一/二/四/六/十三 |
| **执行操作者**（一人公司主理人） | 学习落地步骤 | 五/六/七/十四 |
| **深度研究型**（学者/咨询师） | 验证权威背书 | 二/三/十/十四 + 引用汇总 |

## 二、评分模型深度推导

### 2.1 维度权重设计矩阵

```
维度类型      权重区间     强制包含？
─────────────────────────────────
核心业务能力   50-60%      ✅
硬约束（合规） 20-30%      ✅（受监管行业）
经济性         10%         ✅
长期价值       10%         ⭐推荐
```

### 2.2 评分标度校准

| 评分 | 含义 | 典型场景 |
|------|------|---------|
| 9-10 | 行业领先 / 唯一具备 | WorkBuddy PIA 二星+ / 飞书全模态 |
| 7-8 | 主流能力 | 千问 100 万上下文 / 豆包多模态 |
| 5-6 | 可用但有缺陷 | 千问 IM 接入弱 |
| 3-4 | 明显短板 | 豆包企微支持差 |
| 1-2 | 几乎不可用 | 缺数据本地化 |

### 2.3 加权总分验证

**合格推荐**：冠军得分 ≥70 且领先亚军 ≥5 分
**压倒性推荐**：冠军得分 ≥80 且领先亚军 ≥10 分
**平局场景**：需要追加决策树维度

## 三、ROI 计算标准公式

### 3.1 单项 ROI

```
单项 ROI = (替代前人力成本 - AI 替代后成本) × 12 / AI 工具年成本
```

### 3.2 综合 ROI（含隐性收益）

```
综合 ROI = (显性节省 + 隐性收益) × 12 / 总投入

显性节省：助理/外包/学习成本
隐性收益：错误率降低 × 损失 + 客户满意度 ↑ × 续保率
```

### 3.3 决策阈值

```
ROI > 30 → 立即投入
ROI 10-30 → 30 天试用评估
ROI < 10 → 不推荐或重新选型
```

## 四、风险预案分级标准

### 4.1 风险严重度（v2.0 三级体系 · 与 SKILL.md / template-checklist.md 统一）

| 等级 | 后果 | 触发条件示例 |
|------|------|------------|
| 🔴 致命 | 吊销资格/承担刑责/重大经济损失 | 销售误导/客户隐私泄漏/重大合规违规 |
| 🟡 高频 | 业务影响但可恢复（中等频率发生）| 续保季卡顿/营销违规/工具响应慢 |
| 🟢 注意 | 体验下降或低频小问题 | UI 不友好/偶发 bug |

### 4.2 兜底方案设计原则

**3 个兜底要素**：
1. **可执行性**：出问题时能立即启动
2. **可追溯性**：所有兜底动作有审计日志
3. **可回退性**：业务能恢复到原状

## 六、案例设计模式

### 6.1 案例真实性边界

| 案例类型 | 标注方式 | 适用场景 |
|---------|---------|---------|
| **真实案例** | 注明访谈时间/来源 | 有可追溯访谈记录 |
| **类型化案例** | "经验估算 / 行业观察"| 基于公开报道整理 |
| **假设案例** | "假设性推演"| 用于说明可能性 |

### 6.2 案例差异化矩阵

```
横轴：人员规模（1人 / 1+N 团队 / 全职团队）
纵轴：客单价（普通 / 中产 / 高净值）

4 个象限必须覆盖：
├─ 1 人 × 普通客单（最低门槛）
├─ 1+N 团队 × 普通客单（团队管理）
├─ 1 人 × 高净值（专业能力）
└─ N 团队 × 高净值（规模化）
```

## 七、用户专属建议设计

### 7.1 画像要素清单

```yaml
地理位置: [城市/区域 + 特征]
人力资本: [年龄/经验/家庭]
财务画像: [收入/支出/负债]
痛点: [3-5 个真实痛点]
机会: [3-5 个本地化机会]
约束: [主业/时间/资金]
```

### 7.2 数字匹配原则

每个数字必须能溯源：
- 主业净收入 → 基于 [城市] + [年龄] + [行业] 公开数据
- 月供 → 基于 [贷款额] + [利率] + [年限] 计算
- 副业收入 → 保守估计 = 行业基准 × 70%
- 现金流缺口 → 收入 - 支出 - 负债
